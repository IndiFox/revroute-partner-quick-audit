# Экспресс-аудит партнёрской программы

**Что мешает партнёру рекомендовать ваш продукт — и что улучшить первым?**

Открытый скилл RevRoute разбирает презентации, условия, оферту и другие материалы программы. Вы получаете сильные стороны, пробелы по шести рычагам рекомендации, до трёх приоритетных действий и список недостающих данных. Если для следующего шага нужен готовый материал, скилл добавит сообщение, расчёт, вопросы квалификации или план проверки демо.

## Попробовать

1. Скачайте [SKILL.md](SKILL.md) и прикрепите его к чату вместе с материалами своей программы. Можно загрузить несколько документов: презентацию, условия или договор, описание продукта, переписку и заметки со встреч. Достаточно и одного документа; лендинг необязателен.
2. Отправьте:

> Примени приложенный скилл к нашей партнёрской программе. Покажи сильные стороны, подтверждённые пробелы и главный барьер для партнёра. Объясни, на чём основаны выводы, что улучшить первым и каких данных не хватает. Предложи ближайшую проверку.

Ориентир результата — 500–800 слов; подробности можно запросить отдельно. Вся методология для запуска находится внутри одного SKILL.md. Чтение PDF, сканов и страниц зависит от приложения; можно приложить извлечённый текст. Это разбор доступных материалов, а не подтверждение фактической работы программы.

[Учебный пример: три источника → диагноз → приоритеты и недостающие данные](examples/example.md). Кейс адаптирован по мотивам практического разбора, с изменёнными деталями. Пример редакционно обновлён для 0.4.0; это иллюстрация результата, а не новый независимый тест модели.

## Что проверяет скилл

| Рычаг | Что становится понятнее |
|---|---|
| Польза клиенту | Кому и когда рекомендовать продукт |
| Уверенность в качестве | На чём основано обещание результата |
| Социальная валюта | Как рекомендация усиливает авторитет партнёра для его аудитории |
| Личная выгода | Что он получает относительно своих усилий |
| Защита репутации | Чем партнёр рискует из-за продукта, бренда и поведения представителя |
| Лёгкость действия | Можно ли сделать следующий шаг без лишней подготовки |

Перед выбором приоритетов скилл проверяет предпосылки канала: подтверждённый спрос, носителей доверия, экономику обеих сторон и готовность исполнять обязательства. Процент комиссии рассматривается вместе с доступным объёмом, затратами и усилиями партнёра. Отдельно проверяются существенные правила: закрепление, выплаты, ответственность и согласованность материалов.

Скилл различает подтверждённый пробел, гипотезу и отсутствие данных. Он не переносит модельные расчёты в действующие условия, а предложения партнёру — в обещания его клиенту. Общий рейтинг и прогноз продаж не вычисляются.

## Установка как навыка

В приложении с поддержкой [Agent Skills](https://agentskills.io/specification) поместите этот репозиторий в папку навыков под именем `revroute-partner-quick-audit`.

Для проекта Codex:

```sh
git clone https://github.com/IndiFox/revroute-partner-quick-audit.git .agents/skills/revroute-partner-quick-audit
```

Начните новую сессию в проекте и вызовите `$revroute-partner-quick-audit`. [Официальная инструкция по каталогам навыков](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills). Для обычного чата установка не нужна: достаточно SKILL.md.

## Методика и границы

Основа — презентация Александра Марчука «Партнёрский канал продаж в 2026» и сопровождающий спикерский текст RevRoute. Главный тезис: рекомендация — репутационная транзакция; партнёр ставит на кон доверие своей аудитории.

**R = (V × C) + S + B − RR − F** — смысловой чек-лист: польза и уверенность усиливают друг друга, социальная валюта и выгода добавляют мотивацию, риск и трение её уменьшают. Формула не используется как калькулятор. Качественные статусы, работа с источниками и формат результата — адаптация для скилла. Это экспресс-разбор по шести рычагам, а не полный аудит всех зон программы.

Версия **0.4.0, beta**. Качество зависит от модели: [источники методологии, проверки и ограничения](TESTING.md). Для глубокой оценки нужны данные и отдельный разбор.
